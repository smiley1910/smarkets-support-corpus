# Smarkets Reply Style Overrides

Companion to the pinned voice skills. Apply these standing preferences on every Smarkets/SBK customer draft.

## Procedure

1. Answer in organic prose by default, even when the customer numbered their questions. Prose carries multi-part API answers without looking generated.
2. State API behaviour directly as fact. Never attribute to documentation.
3. Translate every limit or rule into what the customer does next. Limits alone read as doc parroting.
4. Route commercial use to the affiliates team instead of adjudicating it here.

## Hard rules

- Default to prose. Number only when prose cannot carry distinct answers without confusion. Numbering a routine info reply is an AI tell.
- Never write "our documentation", "API documentation states", "per the docs", or "as documented". Say the behaviour: tokens last 30 minutes, quotes allow 50 per 60 seconds.
- Practice first: follow each stated limit with the action. Batching, caching, spacing, buffer intervals, watching stop timestamps, treating 401 as expired belong in the same paragraph as the numbers.
- Commercial use (tools displaying odds, multi user integrations, betting for others, redistributing data) is never approved in the ticket. Direct to affiliates@gmail.com and ask for product, data use, jurisdictions, and volumes.

## Pitfalls

- Listing limits without application reads as parroting the spec. Attach the practice to the step it affects.
- Hedging a refusal with documentation language weakens authority. State the position, then the reason.
- Rewriting Michael-approved direct wording into a warmer register undoes his edit. Fix grammar and factual ambiguity only.
- Softening a refusal with banned softeners stays banned even when asked to be kinder — warmth comes from thanking the customer for checking first, mirroring their facts back, and framing the next step as welcome, never from hedging the decision.
