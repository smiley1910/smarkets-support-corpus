## 2. Hallucination flags (requested categories)

**a) Amend handling — REWORD.** Verified today against the live spec: no PUT, no PATCH, no amend endpoint (18 paths, methods only GET/POST/DELETE). Cancel + replace is the only mechanism, so the draft's substance is right. But "amend" appears nowhere in the API docs or spec (the single spec hit for "amend" is the horse-racing state enum `amended_result`). Frame it as the absence of an amend route, not a supported feature.

**b) Error shape — DELETE.** "Error outside scope" is not documented anywhere. No scope-related error code exists among the 92 live error codes. Also check any generic error-shape claim: quotes and order endpoints use an **inline** 429 schema `{"error_type": "RATE_LIMIT_EXCEEDED", "data": string|object}` with **no** `count`/`limit`/`expiry`; only most GET endpoints use `RateLimitError` with `count`/`limit`/`expiry` (RFC 2822, not ISO 8601). The older `api-scope-confirmation.txt` line 43 ("The `expiry` field tells you exactly when the window resets") is wrong for quotes/orders and is already corrected in `rate-limits.md` L47-67. Do not repeat it.

**c) Live vs delayed quotes — KEEP WITH CAVEAT.** Live spec: *"If session token is not sent, these prices will be delayed."* Live = approved API account + session token. Without a token the endpoint still returns a full book, but delayed (`noauth-quotes-endpoint.md`).

**d) P2P-only book — CAVEAT NEEDED, NOT SPEC-DOCUMENTED.** `/v3/markets/{ids}/quotes/` returns the raw peer-to-peer order book and excludes first-party market-making liquidity the website merges in (`quotes-endpoint-behaviour.md` L27-42; `noauth-quotes-endpoint.md` L54-64). This is internal analysis from field evidence, explicitly flagged as needing an api@smarkets.com ruling — do not state it as documented API behaviour. If the draft implies the customer will see the same prices as the website, that is wrong; if it omits the caveat, add a light-touch version.

## 3. Missing caveats (add these)

- **(a) Benchmarking prohibition — highest priority for a Betfair algo.** §5: *"usage of the API or its data to benchmark markets, prices, liquidity or systems is not permitted."* Cross-exchange price comparison is the exact overlap deferred to api@smarkets.com in the prior scope reply (`api-scope-confirmation.txt` Q8). Do not give a clean yes.
- **(b)** §7 Unfair Trading: *"latency arbitrage or court-siding, where delays are exploited to disadvantage other customers"* is a suspension ground.
- **(c)** §2 permitted use only: *"view market prices and place bets on their Smarkets account. All other uses are strictly prohibited, including but not limited to, odds scraping, concealing API calls, browser impersonation or reverse engineering."*
- **(d)** §5 data: no sharing/selling/distributing platform data without written approval.
- **(e)** No sandbox/test environment — integration testing uses live funds (`verified-api-facts-deep-audit.md` "Claims NOT Verified"; `api-scope-confirmation.txt` Additional points).
- **(f)** No streaming/WebSocket; API is REST only. Use the scoped denial wording from `deprecated-streaming-api-and-sio-live.md` L85 (never claim no websocket exists anywhere at Smarkets).
- **(g)** In-play betting delays: 4s horse racing/darts, 8s all other events (General Rules 8.2.1) — they affect order placement, not just data.
- **(h)** Order lifetime on halts: default is `good_til_halted`; `good_til_cancelled` is cancelled when the market goes live; only `keep_in_play` survives a halt; all types cancelled on reduction factor. Material to a cancel/replace strategy.
- **(i)** Session token TTL 30 minutes with sliding renewal (`api-technical-quirks.md` L15-23).
- **(j) Pro thresholds count every bet placed, including unmatched and cancelled ones.** Commission FAQ: *"these metrics are based on all bets placed, whether they are unmatched, partially matched or fully matched. The limits are based on the initial bet placement."* Amount staked = *"the liability of all bets placed."* An algo can cross 1,500 bets/month well below 100k staked. This is the single most useful pre-sales caveat for this customer.
- **(k)** Cancel + replace is not free or guaranteed: cancel can fail (`ORDER_CANCEL_REJECTED_TOO_LATE`, `_NOT_LIVE`, `_NOT_FOUND`, `_TRADING_SUSPENDED`, `_ACCOUNT_SUSPENDED`), cancel-all is capped at 1/60s, cancel-one at 10/s, placement at 10/s — the cycle consumes quota.
- **(l)** 1,200/60s applies per account to authenticated requests; unauthenticated public endpoints are not rate-limited (18,141 requests/90s with zero 429s) — but using that to dodge limits still engages §5/§6.1/§7.
- **(m)** Per-endpoint caps are concurrent caps, not additive allocations (sum 1,882 rpm > 1,200 global). Quotes 50/60s is the API-user tier; non-API accounts observed at 20/60s, and the response header is ground truth for the account's tier.
- **(n)** Pre-approved events/markets list is not published; it is set per account at application and changes go via api@smarkets.com.
- **(o)** £150 is "or account currency equivalent"; refund requires **permanent** withdrawal from API usage.
